# Spec Plan · 接入说明

面向：要把这套 UI 接到真实后端（writ 项目 `GET /api/extract` 等契约）的开发者。
运行：静态文件即开即用（React UMD + Babel standalone，无构建步骤），入口 `Spec Plan.html`。

## 2. 数据接入：ExtractResult → 页面

页面唯一消费的数据对象是 `PLAN_MODEL = buildPlanModel(PLAN_SOURCE)`。

```
GET /api/extract ──► ExtractResult { points, decisions }
                          │
        adaptExtract(apiResult, docMeta, uiOverlay)   ← plan-contract.jsx
                          │
                     PLAN_SOURCE ──► buildPlanModel() ──► PLAN_MODEL
```

最小接入（替换 `plan-fixture.jsx` 尾部三行）：

```js
const api = await fetch('/api/extract?doc=plan-data-backend.md').then(r=>r.json());
const PLAN_SOURCE = adaptExtract(api.result, docMeta, uiOverlay);
const PLAN_MODEL  = buildPlanModel(PLAN_SOURCE);
```

### 契约字段 vs UI 扩展字段

**契约字段**（与后端 `types/domain.ts` 一致，勿改名）：
- `ExtractedItem`: `id` `kind`(8 类) `label?` `refs[]` `text` `source` `confidence?` `anchor?`
- `DecisionCard`: `pointId` `label?` `chosen` `rationale` `rejected[{option,reason}]` `status`

**UI 扩展字段**（adapter 的 `uiOverlay` 填充；后端格式细化时只改 overlay，渲染层不动）：
- `point.title`（列表标题）、`point.role`（同 kind 内的形态分流：gate/bug、in/out、step）
- `point.ui.*`：各节专用展示数据（风险 `lvl/risk/fix`、前置 `blocks`、待确认 `owner/due`、做法 `num/file/pts/subs`）
- `decision.question / pick / facts / cost / core`
- 节级配置 `PLAN_SECTIONS`：kicker / lead / 富块（§1 模型对照表、§4 模块树）

**标签体系**：后端稳定标签为 `^[GDRPQ]\d+$`；`B\d+`（bug）、`S\d+`（做法）、`A\d+`（验收）、`§1…§8`（章节）为前端导航伪标签，由 `normLabel()` 归一。悬空引用不报错，渲染为不可点的灰芯片。

### buildPlanModel 派生了什么（全自动，勿手工维护）
- `points`：label → {title, brief, sec, refs…} 注册表（芯片悬停预览 / 跳转）
- `inbound`：引用图入边（谁引用了我 = 依据链）
- `sections`：8 节 + 徽标（"5 约束 / 4 已定 / 2 中"等按内容计数）
- `legend`：标签图例计数；右栏审阅清单的数量同样全部派生

## 3. 8 节渲染器注册表（文档格式细化时的扩展点）

`plan-sections.jsx` 尾部：

```js
const SECTION_RENDERERS = { goal: GoalSection, scope: ScopeSection, … };
```

- 渲染器统一签名 `({ sec, points, ctx })`：`sec` 节定义（kicker/lead/extras）、`points` 该节信息点、`ctx` 交互回调（当前只有 `{signed, toggleSign}`）。
- **替换某节形态** = 重写对应组件；**新增节** = `SECTION_DEFS`（plan-contract.jsx）加一行 + 注册渲染器；未注册的节自动走 `GenericSection` 兜底（label + 正文列表），后端先行新增节类型时页面不会白屏。
- 正文里要可跳转引用时用 `<T s={point.text}/>`（解析 `{G1}` token）或 `<Ref l="G1"/>`。
- 节标题元素务必保留 `data-sec` / `data-pt` / `data-screen-label`；信息点容器保留 `data-pt={label}`——跳转总线、scroll-spy、审阅清单都靠它们定位。

## 4. AI 接入：AgentService

所有 AI 行为都经 `agent-service.jsx` 的单一接口，UI 不感知实现：

```js
agent.send(request, { onThinking, onReply }) → cancel()
```

request 分型：`chat`（对话，可带选区 quote）、`selection-op`（转决策卡 / 提风险 / 提待确认 / 解释）、`analyze-notes`（批注批量分析）、`command`（⌘K 的 ai-review / ai-refs）。

接真实 agent（如 `claude -p --output-format stream-json` 或后端 SSE）：

```js
function createRealAgent(cfg){
  return {
    send(req, cb){
      const es = new EventSource(`/api/agent?type=${req.type}&q=${encodeURIComponent(req.text||'')}`);
      es.onmessage = (e)=>{
        const ev = JSON.parse(e.data);
        if(ev.type==='progress') cb.onThinking(ev.label);          // 过程态 → 对话「思考中」
        if(ev.type==='final'){ cb.onThinking(null);
          cb.onReply({ body: ev.paragraphs, acts: ev.actions }); es.close(); }
      };
      return ()=>es.close();                                        // 会话切换时被调用
    },
  };
}
```

替换点只有一处：`plan-app.jsx` 中 `agent.current = createMockAgent()` 改为你的实现。
回复里的行动卡 `acts:[{icon, kind, title, sub, pt?|sec?}]`——带 `pt` 点击跳标签、带 `sec` 跳小节。

**内联改写**（选区改写动画 `doRewrite`）当前为本地演示；接入时把改写文本 POST `/api/rewrite`，用返回文本替换 `span.textContent`。

## 5. 持久化与本地状态

| 状态 | 存储 | key |
|---|---|---|
| 主题 / 字体 / 字号 / 行距 | localStorage | `spec-settings`（ds-shell.jsx） |
| 前置拍板 P1–P4 | localStorage | `spec-plan-signed`（→ 接入时改 POST 后端） |
| 批注 / 会话 / 历史 / 已读进度 | 内存（刷新重置） | 接入时分别对接 annotations / 会话存储 / 版本记录 |

`usePersistedState(key, initial)`（plan-hooks.jsx）是统一入口，要加持久化状态用它。

## 6. 已知边界

- 批注高亮（`anno-mark`）演示用 `NOTE_ANCHORS` 的锚点子串匹配；真实接入应改用后端 `annotation.anchor`（结构化锚点）定位。
- 抽取结果不持久化、每次重算（沿用后端约定），所以顶栏「同步 / 刷新」重拉 extract 即可。
- 划选的「转决策卡 / 提风险」等操作 mock 只回话不真改文档；真实实现应走 agent 修改 markdown 后重拉 extract 渲染。
