# 文档模型

## 范围

scribepad 审阅两类文档：plan 用于执行前对齐意图，review 用于执行后让不读代码的裁决者
低成本建立信任。Markdown 是内容事实源；稳定标签是批注、引用和 signoff 的锚点。

## Plan

Plan 由目标、边界、决策、做法、验收、风险、前置和待确认组成。缺失或非标准结构允许
降级解析，但不得导致抽取失败。`G/D/R/P/Q/B` 标签表示稳定的语义单元，正文中的标签
引用形成可导航依据图。

## Review

Review 固定包含五个职责不同的部分：

| 部分 | 职责 |
| --- | --- |
| 需要裁决 | 暴露计划外决定、重大偏差和回退成本 |
| 计划对账 | 逐条覆盖批准稿，标明按计划、偏差、未做和新增 |
| 声明与证据 | 将完成声明绑定到可执行核验 |
| 遗留与假设 | 显式列出 deferred、assumption 和 limitation |
| 变更明细 | 提供需要下钻时使用的实现索引 |

Review H1 使用 `Review:` 前缀；裁决、声明、遗留分别使用稳定的 `Dx`、`Cx`、`Lx` 编号。

## 写作约束

- 结论先行：每个单元第一句说明决定、结果或使用者后果。
- 面向不读代码的裁决者；代码名词只出现在证据或必要补充中。
- 结论性声明必须挂可执行证据；无法验证时标明 `unverified` 和原因。
- 裁决项不超过 7 条；没有裁决也保留该节并显式说明。
- 计划对账以批准稿为基准，逐条覆盖且不遗漏。
- 每个裁决单元自包含背景、选择、备选、理由和回退成本。
- 标签分配后保持稳定，不因排序或文字改写而变化。

## Review 模板

```markdown
# Review: <一句话说明交付结果>

> plan: <批准稿路径> · commits: <base>..<head>
> 门禁: typecheck ✅ · lint ✅ · unit ✅ · e2e ✅

## 1. 需要你裁决

### D1. [风险标签] <决定及其后果>

- **背景**：<发生了什么>
- **我选了**：<方案>
- **备选**：<另一条路及其代价>
- **为什么没停下来问**：<理由>
- **若否决**：<回退成本和影响>
- **证据**：<commit / file / test>

## 2. 计划对账

| plan 条目 | 状态 | 说明 |
| --- | --- | --- |
| <条目> | ✅ 按计划 | — |

## 3. 声明与证据

| # | 声明 | 证据 | 核验方式 |
| --- | --- | --- | --- |
| C1 | <声明> | <证据> | `<命令>` → <预期> |

## 4. 遗留与假设

- **L1 [deferred]** <内容> —— 触发条件：<何时处理>

## 5. 变更明细

- `<hash>` <变更> — <涉及位置>
```

## 识别契约

- H1 以 `Review:` 或 `Review：` 开头时判为 review；否则命中至少两个 review 专属节名时判为 review。
- 裁决标题为 `### D<n>. [<tag>] <title>`，字段使用粗体引导的列表项。
- 计划对账和声明证据使用 GFM 表格，声明首列使用 `C<n>`。
- 遗留项形如 `**L<n> [<kind>]** <text> —— <触发条件|验证方式>：<内容>`。
- 畸形或缺失字段降级为空值或 `unknown`，不抛出异常。

Review 产物存入 `$XDG_STATE_HOME/scribepad/reviews/`，再通过 scribepad 进入人工验收。
