# Review 文档模版与写作要求

> 本文档是 review 文档（交付审阅报告）的权威模版：执行 agent 产出 review 文档、
> scribepad 抽取（core/extract 的 review 路径）、前端渲染三方共同遵守的契约。
> 定位：plan 文档解决"做之前对齐意图"，review 文档解决"做完之后，一个不读代码的
> 人如何低成本地建立信任并给出裁决"。

## 解决的问题（结构溯源）

| 问题 | 落到的结构 |
| --- | --- |
| P1 自述不可信 | §3 声明与证据（每条声明挂可执行核验）+ 头部门禁快照 |
| P2 注意力分层 | §1 裁决清单排最前 + 头部阅读路径 + §5 明细沉底 |
| P3 计划-执行偏差 | §2 计划对账（零遗漏表），偏差项升级进 §1 |
| P4 反馈闭环 | 单元自包含 + 稳定编号 Dx/Cx/Lx（批注 / signoff 锚点） |
| P5 遗留显性化 | §4 遗留与假设（要求签字） |
| P6 审阅状态 | 单元粒度 = signoff 粒度，编号全生命周期不变 |

## 模版

````markdown
# Review: <一句话说清这次交付了什么>

> plan: <批准稿路径> · commits: <base>..<head>（N 个）· 日期: <yyyy-mm-dd>
> 门禁: typecheck ✅ · lint ✅ · unit 248 ✅ · e2e 12 ✅ —— 复核: `npm run gate`
> 建议路径: §1 裁决(5min) → §2 对账(3min) → §4 签字(2min)；§3/§5 供抽查

## 1. 需要你裁决（按风险降序，≤7 项）

### D1. [擅自决策] <第一句话就是决策本身>

- **背景**：执行到 <哪步> 时发现 <什么>，plan 未覆盖
- **我选了**：<方案>
- **备选**：<另一条路及其代价>
- **为什么没停下来问**：<理由>
- **若否决**：回退成本 <低/中/高>，影响 <范围>
- **证据**：<commit> / <file:line>

## 2. 计划对账

| plan 条目 | 状态 | 说明 |
| --- | --- | --- |
| <条目> | ✅ 按计划 | — |
| <条目> | ⚠ 有偏差 | → D2 |
| <条目> | ❌ 未做 | <原因> → L1 |
| （plan 外） | ➕ 新增 | → D1 |

> 承诺：本表逐条覆盖批准稿全部条目，无遗漏。

## 3. 声明与证据

| # | 声明 | 证据 | 核验方式 |
| --- | --- | --- | --- |
| C1 | <结论性声明> | <commit/测试名> | `<命令>` → 期望 <输出> |
| C2 | <声明> | ⚠ unverified | <为什么核验不了> |

## 4. 遗留与假设（需签字："我知道这些没做"）

- **L1 [deferred]** <内容> —— 触发条件：<何时该做>
- **L2 [假设]** <内容> —— 验证方式：<怎么验>
- **L3 [已知限制]** <内容>

## 5. 变更明细（下钻用，可整节跳过）

- `<hash>` <一句话> — <涉及文件>
````

## 硬性写作要求

1. **无裸声明**：结论性声明必须挂证据；给不出的标 `⚠ unverified` + 原因。核验方
   式必须可执行，禁止"见代码"。
2. **裁决项上限 7**：超了说明执行时该问没问——这本身作为一条流程问题写进 §1。零
   项也要显式写"本次无裁决事项"，不许省略该节。
3. **对账零遗漏**：§2 以**批准稿**（非草稿）为基准逐条覆盖。
4. **单元自包含**：每个 Dx 不看其他节就能裁决（背景/选择/备选/回退成本齐备）。
5. **结论先行**：每个单元第一句就是决策或声明本身，不许铺垫。
6. **编号稳定**：Dx/Cx/Lx 一经分配不变——批注和 signoff 都锚在它们上。

## 标签

- 裁决卡风险标签集（H3 的 `[…]`，自由扩展）：`[不可逆]` `[对外行为]` `[擅自决策]`
  `[安全]` `[性能]` `[流程]`
- §4 类别标签：`[deferred]` `[假设]` `[已知限制]`（抽取映射为
  deferred / assumption / limitation，未知值降级 unknown）
- §2 状态符号：`✅ 按计划` `⚠ 有偏差` `❌ 未做` `➕ 新增`（缺符号时按关键词匹配，
  再不中降级 unknown）

## 机器识别契约（抽取路径依赖，改动需同步 core/extract）

- **docKind 判定**：H1 以 `Review:` / `Review：` 开头 ⇒ review；否则 review 专属
  节名（裁决 / 计划对账 / 声明与证据 / 遗留）命中 ≥2 个 ⇒ review；否则 plan。
- **§1 单元**：H3 形如 `### D<n>. [<tag>] <title>`，正文为粗体引导的 bullet
  （背景 / 我选了 / 备选 / 为什么没停下来问 / 若否决 / 证据）。
- **§2 / §3**：GFM 表格，列序如模版；§3 首列为 `C<n>` 标签。
- **§4 单元**：list item 形如 `**L<n> [<kind>]** <text> —— <触发条件|验证方式>：<...>`。
- 所有形状缺失/畸形时**降级不 throw**（缺字段留空、未知值归 unknown），与 plan
  抽取的 degrade 铁律一致。

## 生成与存放

执行 agent 完成执行后按本模版产出，存放到
`$XDG_STATE_HOME/scribepad/reviews/<encoded-repo-path>/<yyyymmdd>-<topic>.md`
（路径编码与 plans 目录一致：绝对路径 `/` → `-`），随后 `scribepad <path> --wait`
进入人工验收。
