# 目录规范

## 顶层归属

| 位置 | 唯一职责 |
| --- | --- |
| 仓库根目录 | 项目入口和全局工具配置 |
| `core/` | 平台无关领域规则 |
| `types/` | 跨运行时契约与 Port |
| `server/` | Application、Delivery、Adapter 与 Composition Root |
| `client-next/` | 浏览器面板 |
| `tests/` | 自动化验证与测试资产 |
| `docs/` | Design 和 Spec |

## 归属原则

- 按语义所有者和变化原因聚合，不按文件类型或临时任务阶段分层。
- 跨模块复用放入能够完整拥有其语义的最低稳定层。
- 不创建 `common/`、`utils/`、`helpers/` 等无明确所有者的容器。
- 只有同一职责需要多个协作实现时才拆目录，不预留空层级。
- 构建产物、缓存、运行数据和本地状态不得提交。

## 变更门禁

- 依赖符合 Architecture 且没有反向依赖、循环依赖或跨层捷径。
- 目录迁移一次完成；旧路径、重复实现、兼容逻辑和失效引用同步删除。
- 测试、文档和产品代码分别承担验证、说明和运行职责。
