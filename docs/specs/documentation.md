# 文档规范

## 分类

项目文档只分为 Design 和 Spec。Design 定义跨实现稳定的产品语义与系统模型；Spec 定义
全项目共同遵守的工程约束。README 和 AGENTS 只负责入口导航，不建立新的事实源。

## 内容准入

一条信息只有同时满足以下条件才进入项目文档：

```text
项目级有效
AND 相对稳定
AND 无法从代码、测试或公开接口可靠推导
AND 存在唯一归属
```

精确运行行为由代码、测试和公开接口维护；局部原因写相邻注释；任务拆解和完成历史由
计划、Issue、提交和 Git 维护；一次性分析与运行证据不进入长期文档。

## 唯一真源

- 同一事实只在一个文档定义，其他位置只引用。
- Spec 不复制当前目录树、文件名或内部调用。
- Design 不复制路由、字段、能力矩阵等可由实现推导的信息。
- 文档被替代、吸收、完成或过时时直接删除，不保留归档副本。

## 写作与门禁

- 中文为主，技术术语保留英文；按问题组织，不维护日期、版本和状态字段。
- 新文档必须拥有无法合并到现有文档的唯一职责。
- 移动或删除后同步更新入口、引用和相对链接。
- 示例必须符合当前公开行为。
